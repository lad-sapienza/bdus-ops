# bdus-ops

Deployment toolbox for **this** BraDypUS install: two instances (`prod`, `demo`)
on one private VM behind a separate reverse-proxy VM. Everything is driven by one
file, `config.env`, and one command, `bdus`.

The narrated procedure — with the *why* of every step and the manual fallback —
is [`DEPLOY-RUNBOOK.md`](DEPLOY-RUNBOOK.md). The scripts here are the "just run it"
view of the same thing. The **proxy VM is done by hand** following the runbook.

---

## Install (on the app VM)

```bash
sudo apt-get install -y git            # if needed
git clone <your-private-remote>/bdus-ops.git /srv/bradypus/ops   # any path is fine
cd /srv/bradypus/ops
cp config.env.example config.env && $EDITOR config.env           # set the paths / IPs
sudo ln -s "$PWD/bin/bdus" /usr/local/bin/bdus

bdus help
```

`config.env` is git-ignored (per-server). No secrets are stored in it — the
Postgres password is generated by `bdus init` into `<instance>/.env` (`chmod 600`).

## First deployment

```bash
bdus setup host                 # sudo: docker group, daemon.json, ufw, DOCKER-USER fw, /srv/bradypus
#   ↳ log out / back in once (docker group)

bdus init prod                  # writes bradypus.yml + .env + bdus.override.yml, pull, up, wait healthy
bdus init demo

bdus app add demo --name bdus_demo --engine sqlite --email admin@lad-sapienza.it
bdus app add prod --name siti_scavo --engine pgsql --email admin@lad-sapienza.it

# proxy VM: by hand — see DEPLOY-RUNBOOK.md, Parte B
sudo cp etc/cron.d/bdus-backup /etc/cron.d/bdus-backup   # adjust the user/path first
bdus status
```

## Day to day

| task | command |
|---|---|
| health of everything | `bdus status` |
| tail logs | `bdus logs prod -f` |
| back up now | `bdus backup all` |
| new release 5.4.8 | `bdus update all 5.4.8` |
| restore prod (latest) | `bdus restore prod` |
| add an app | `bdus app add prod --name X --engine pgsql --email …` |
| list apps | `bdus app list` |
| psql into prod | `bdus psql prod bdus_siti_scavo` |
| check for drift | `bdus doctor` |

Full flag reference: [`docs/COMMANDS.md`](docs/COMMANDS.md).

## Requirements

- Debian (bash 4+), Docker CE + `docker compose` v2, `curl`, `openssl`.
- The app VM needs network access to `ghcr.io` to pull images.

## Layout

```
bin/bdus            dispatcher (symlink this to /usr/local/bin/bdus)
lib/common.sh       config load + helpers, sourced by every subcommand
setup/host.sh       `bdus setup host`
libexec/bdus-*      one file per subcommand (each prints its own --help)
vendor/add-app.sh   copy of the BraDypUS repo helper, used by `bdus app add`
etc/cron.d/         sample cron
config.env.example  copy to config.env
DEPLOY-RUNBOOK.md   the narrated procedure (source of truth for paths/topology)
```
